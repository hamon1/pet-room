# 1단계 트러블슈팅 기록 (2026-10-29)

## 1. CI에서 실패 원인 로그를 볼 수 없음

- **상황**: 백엔드 테스트 단계가 `exit code 1`로만 실패하고, 작업 환경에서 Actions 원본 로그를 내려받을 수 없었음
- **조치**: 테스트 출력을 파일로 남기고, 실패 시 `error:`, `FAILED`, `Caused by` 줄만 골라 Actions 오류 표시(annotation)로 남기는 단계를 추가
- **결과**: PR·커밋 화면에서 실패한 테스트 이름이 바로 보임

## 2. 중복 이메일 테스트가 409 대신 400을 받음

- **상황**: `" ME@EXAMPLE.COM "`처럼 앞뒤 공백과 대문자를 섞어 가입하면 409(중복)를 기대했지만 400이 옴
- **원인**: 서비스 계층의 정규화(공백 제거·소문자 변환)보다 요청 검증(`@Email`)이 먼저 실행되고, 앞뒤 공백이 있는 문자열은 이메일 형식이 아님
- **조치**: 공백 처리는 화면(입력값 trim)에서 맡고, 서버 테스트는 대소문자 무시만 검증하도록 수정
- **배운 점**: 정규화를 어디서 하는지(클라이언트 / 검증 전 / 서비스)를 정해 두지 않으면 검증 순서 때문에 의도와 다른 오류가 남

## 3. Next.js 빌드가 보안 취약점으로 중단됨

- **상황**: `next@16.4.0`으로 빌드하자 알려진 보안 취약점이 있다며 빌드가 실패
- **확인**: `npm audit`에서 16.0.0~16.4.0 범위에 심각도 critical 권고가 확인됨 (이미지 최적화 API 원격 코드 실행 등)
- **조치**: 수정 버전 `16.4.3`으로 올리고 버전을 고정(`--save-exact`), `npm audit` 0건 확인
