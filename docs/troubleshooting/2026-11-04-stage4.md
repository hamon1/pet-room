# 4단계 트러블슈팅 기록 (2026-11-04)

## 1. 테스트 전용 컨트롤러가 등록되지 않음 (404)

- **상황**: 500 응답을 확인하려고 테스트 클래스 안에 오류를 내는 컨트롤러를 두었는데 404가 남
- **원인**: Spring Boot 테스트는 테스트 클래스와 그 안에 선언된 클래스를 컴포넌트 스캔에서 제외함
- **조치**: 테스트 클래스에 `@Import(BoomController.class)`로 명시 등록

## 2. 모의 객체를 다시 설정할 때 NullPointerException

- **상황**: `when(sender.send(any(), anyString())).thenReturn(410)`에서 NPE
- **원인**: `when(...)` 안의 호출이 실제로 실행되면서, 앞에서 설정한 응답 함수가 `null` 인자로 불림
- **조치**: 이미 설정된 모의 객체는 `doReturn(410).when(sender).send(...)` 형식으로 다시 설정

## 3. 구독 해지에서 ClassCastException (500)

- **상황**: `DELETE /api/push-subscriptions`가 500. CI 오류 표시만으로는 원인이 보이지 않아, 테스트 결과 XML에 남은 서버 로그의 예외를 CI 오류로 표시하도록 워크플로를 보강
- **원인**: 이름으로 만드는 삭제 쿼리(`long deleteByEndpointAndUserId`)의 반환값 변환에서 `PushSubscription`을 `Long`으로 바꾸려다 실패
- **조치**: `@Modifying @Query("delete from ...")`로 명시한 삭제 쿼리로 변경 (한 번의 SQL로 삭제, 삭제 건수 반환)

## 4. 직접 구현한 웹 푸시 암호화 호환성 확인

- **확인 방법**: Java로 암호화한 메시지를 Node.js 웹 푸시 구현(`http_ece`, `web-push` 패키지가 사용)으로 복호화 → 4회 모두 원문 일치
- **중간에 발견한 것**: 처음 확인 때 한글이 깨졌는데, 원인은 암호화가 아니라 셸 인자를 Java에 넘길 때의 문자 인코딩이었음 → 메시지를 base64로 넘겨 다시 확인
